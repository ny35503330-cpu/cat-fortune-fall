# Codex委譲テンプレート

## 目的

Claude Codeの `Task(...)` 例を、Codexのサブエージェント委譲でも効く形に変換する。

## 5要素テンプレ

サブエージェントに渡す依頼文は、必ずこの5要素を入れる。

```text
元の目標:
{ユーザーが最初に求めたこと}

この担当の責務:
{今回このエージェントが担当すること}

スコープ制限:
{触ってよい範囲 / 触ってはいけない範囲}

使用してよい道具・避ける道具:
{Read/Grep/Bash/編集/ブラウザ/外部検索などの方針}

受入基準:
{完了とみなす条件。ファイル、出力形式、検証コマンド、報告内容を具体化}
```

## 読み取り専用の調査役

```text
元の目標:
Claude式スキルをCodexでも動く形に移植する。

この担当の責務:
対象ファイルを読み取り、Codex移植で必要なメタデータ、委譲先、注意点を整理する。

スコープ制限:
読み取り専用。ファイル作成・編集・削除は禁止。

使用してよい道具・避ける道具:
Read/Grep/検索系のみ使用。Bashはls/git statusなど読み取りに限定。Edit/apply_patchは禁止。

受入基準:
1. 移植対象ファイル一覧を出す
2. Codexへそのまま移せる項目と読み替えが必要な項目を分ける
3. 危険な1:1移植を箇条書きにする
4. 変更は一切行わない
```

## 実装修正役

```text
元の目標:
Claude式スキルをCodexでも効くスキルへ移植する。

この担当の責務:
指定された1つのスキルだけをCodex形式へ変換する。

スコープ制限:
編集してよいのは .agents/skills/{skill_name}/ 以下のみ。元の .claude/skills は変更禁止。

使用してよい道具・避ける道具:
Read/Grep/apply_patchを使用可。rmや履歴書き換えは禁止。

受入基準:
1. SKILL.mdに name と description がある
2. Claude専用メタデータは本文に退避されている
3. 委譲手順が5要素テンプレになっている
4. quick_validate.py が通る
5. 変更ファイル一覧を報告する
```

## 評価役

```text
元の目標:
移植したCodexスキルが実際に使える品質か確認する。

この担当の責務:
成果物を評価し、直接修正せず、問題点と修正案だけを出す。

スコープ制限:
読み取り専用。SKILL.mdや設定ファイルを直接修正しない。

使用してよい道具・避ける道具:
Read/Grep/検証コマンドのみ使用。Edit/apply_patchは禁止。

受入基準:
1. 発火条件がdescriptionに入っているか評価する
2. Codex非対応のClaude専用挙動が残っていないか評価する
3. サブエージェント委譲文が5要素か評価する
4. Keep/Flag判定と修正案を返す
```

## Generator / Evaluatorループ

Codexでも、生成役と評価役は分ける。

1. Generatorが作る
2. Evaluatorが評価する
3. Evaluatorは直接直さず、フィードバックを書く
4. Generatorがフィードバックを読んで直す
5. メインが実体確認する

この分離により、作った本人が自分に甘く採点する問題を減らす。
